# 02: 抽出共享模型客户端

**What to build:** 让「简历优化」和「面试押题」共用同一份模型调用代码，而不是各写一份。这一片**不改变任何用户可见行为** —— 它是让后续实现变容易的前置整理：先把改动变容易，再做容易的改动。

模型调用层要独立出来的四件事：

1. 发请求（端点、鉴权、超时、环境变量）
2. 剥掉推理模型的思考块
3. 从模型输出里抠出合法 JSON（要能扛住思考块里的花括号、代码围栏、散文里的括号）
4. 思考开关的读取（默认关闭，可用环境变量切回）

优化模块保留自己的提示词与业务逻辑，只把调用层换成共享实现。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 共享模型客户端独立成模块，优化模块与押题模块都能从它 import
- [ ] 优化模块的提示词、业务逻辑、返回结构一字未改
- [ ] 原有全部单元测试（387 条）一条不少地继续通过，测试文件随实现一起迁移
- [ ] 思考开关仍默认关闭，可用环境变量切回
- [ ] 中国版 / 全球版端点切换与鉴权失败的提示文案保持原样
- [ ] 抽出后优化模块里不再残留一份重复的 JSON 解析实现
