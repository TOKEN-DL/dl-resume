# 08: 跨套判重接入 —— 重复押题不再产生重复题

**What to build:** 对同一份简历再次押题时，题库里**不会**出现重复的题。这是整个需求的核心验收点。

两层防线：

- **生成前规避** —— 出题时把该简历已出过的题干清单喂给模型，要求避开。这是主力
- **生成后判定** —— 入库前用 01 号的引擎逐题判重（R1 精确 / R2 近似 / R3 同考点）

套级拦截：若本套与库中任一既有套的重复率 ≥ 55%，**整套不入库**，页面出提示条说明「这套与哪一套高度重复」，同时给一个「仍要入库（只保留不重复的 N 题）」按钮由用户拍板 —— 不硬拦死，因为 R3 可能误杀「同考点但确实不同」的题。

**Blocked by:** 01、07

**Status:** ready-for-agent

- [ ] 再次押题时，模型收到的提示词里带着该简历已出过的题干
- [ ] 完全相同的题不会进题库（数据库唯一约束也不会让它进去）
- [ ] 换措辞的近似题被 R2 拦下
- [ ] 同考点不同问法被 R3 拦下
- [ ] 整套重复率超阈值时，页面出现提示条与「仍要入库（只保留不重复的 N 题）」按钮
- [ ] 点「仍要入库」后只写入不重复的题，重复的题跳过
- [ ] 判重结果在确认层里如实显示（「跳过 N 题重复」）
- [ ] 题库里的同一道题始终只有一份（用户与批次两处隔离都成立）
